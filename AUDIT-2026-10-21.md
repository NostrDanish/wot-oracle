# Security Audit — wot-oracle — status addendum 2026-11-13

This addendum supersedes stale status statements in the 2026-10-21 re-audit. The original report remains below as historical evidence.

## Previous finding status

| Finding | Previous status | Current status |
|---|---|---|
| M-1 — relay TLS certificate verification disabled | Open in 2026-10-21 report | **Closed in current main**: oracle.py uses the websocket client's default TLS verification. The WOT_INSECURE=1 opt-in bypass remains dangerous and must never be set in production. |

The TLS fix is present in current main after merged PR #1 (2026-11-11).

## Current implementation gaps

| ID | Severity | Area | Finding |
|---|---|---|---|
| M-2 | Medium | Event authenticity | Fetched kind-3 events are not signature-verified before their p-tags affect scores. A malicious or compromised relay can return forged follow lists. Add NIP-01 event verification before using relay data. |
| M-3 | Medium | Protocol output | The script writes wot_scores.json only. It does not publish NIP-85 kind-30382 assertions or the kind-10040 provider declaration. It must not be represented as a working NIP-85 provider. |
| M-4 | Medium | Scoring scope | The original implementation used the candidate's own follow set even though follows_map is keyed by seed accounts, producing incorrect/zero scores. A regression test and correction are in draft PR #3; merge only after green CI and review. |
| M-5 | Low | Input/relay handling | The CLI example previously accepted npub-looking values, but the relay filter expects 64-character hex pubkeys. The README now documents hex input. Only the first configured relay is queried; no multi-relay reconciliation is implemented. |
| L-1 | Low | License | LICENSE contains only a short placeholder string, not the full MIT license text. Repository metadata reports NOASSERTION. Do not claim MIT licensing until the owner selects and adds a complete license. |

## Verification in this addendum

- Current oracle.py reviewed for TLS defaults, event parsing, score calculation and output behavior.
- New Python unittest suite and GitHub Actions workflow are introduced in draft PR #3.
- RED run confirms the scoring regression (2 failing tests; empty-seed test passes).
- GREEN status is pending; do not mark the score bug resolved until the full CI run passes.

No production relay publishing, signing, private-key handling or live policy deployment was performed.
