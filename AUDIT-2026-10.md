# Security Audit — wot-oracle — 2026-10-20

## Summary
Single-file Python experiment (oracle.py, read in full): computes Web-of-Trust scores from kind:3 follow lists over public relays. No secrets, no signing. Findings: 0C / 0H / 1M / 1L.

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| M1 | MEDIUM | oracle.py `get_follows()` | `websocket.create_connection(RELAYS[0], sslopt={"cert_reqs": ssl.CERT_NONE})` — TLS certificate verification **disabled** on the relay connection. A network attacker can MITM the follow lists, silently corrupting the WoT scores this tool publishes. | Remove the sslopt override (verification is on by default). |
| L1 | LOW | oracle.py | Bare `except:` swallows errors; single-relay trust (relay.damus.io only) — data-integrity caveat. WoT input (created_at/follows) is untrusted by design. | Catch specific exceptions; cross-check multiple relays. |

## Secrets Check
oracle.py read in full — only public relay URLs; takes pubkeys as CLI args. Org-wide searches for `nsec1`, `sk-`, `xai-`, `nostr+walletconnect://`, `PRIVATE KEY` — **no secrets found**.
