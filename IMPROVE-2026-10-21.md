## Top recommendations (ranked, with effort S/M/L)
1. **One-line TLS fix**: `websocket.create_connection(RELAYS[0], sslopt={"cert_reqs": ssl.CERT_NONE})` disables certificate verification for a wss:// connection — delete the `sslopt` kwarg entirely (websocket-client verifies by default). Do the same sweep fleet-wide; nostr-summary-miner has the identical line. [S]
2. **Fix kind-3 parsing**: `json.loads(m[2]['content']).get('p', [])` reads a legacy content-JSON form; modern kind 3 follow lists live in `p` **tags** (content is often empty). Parse `ev['tags']`, fall back to content-JSON for ancient lists. As written, scores are computed from near-empty data. [S]
3. **EOSE + multi-relay**: the fixed 10-message receive loop on RELAYS[0] silently truncates; loop until EOSE and query 2–3 relays, unioning results. [S]
4. **Make the docstring true or fix it**: header says 'publish kind:30000 list' but the code only writes `wot_scores.json` — either implement NIP-51-kind-30000 publication (addressable follow-set-ish list; consider a `d`-tagged ranked list with NIP-32 rank labels) or correct the docstring. ## Status update — 2026-11-13

The earlier recommendations are still relevant, but the project state has changed:

- TLS verification is enabled by default in current main; WOT_INSECURE=1 is an explicit local-test escape hatch only.
- The score formula had a direction bug: it looked up a candidate's own follows even though the map is keyed by seed accounts. Draft PR #3 adds a regression test and corrects the formula to count trusted seeds that follow each candidate.
- A Python unittest suite and CI workflow are being added in PR #3.
- The README now clarifies that the tool writes wot_scores.json only. It does not yet parse NIP-32 labels, verify fetched event signatures, publish NIP-85 kinds 30382–30385, or publish a kind-10040 provider declaration.
- The old claim that it publishes a kind-30000 list is incorrect and has been removed from the README. NIP-85 is the intended standards-based output path, subject to a separate signing/provider design.
- LICENSE is only a short placeholder; repository metadata says NOASSERTION. Select a license and add the complete text before claiming open-source licensing.

Do not treat this prototype as a production trust provider until source-event verification, scoring policy, NIP-85 publication, provider-key management, CI and independent review are complete.
